# Secure Note-Taking

A secure note-taking platform with JWT authentication, role-based access control,
per-user note ownership, admin user management, pagination everywhere, a deliberately
minimal MongoDB index set, and two aggregation pipelines.

The project is split into two independently deployable packages:

```
secure-note-taking/
├── backend/     Node 22 + Express + Mongoose REST API (deploy to Render)
│   ├── src/                 routes, controllers, models, middleware
│   ├── scripts/             admin seeding + end-to-end smoke test
│   ├── render.yaml          Render blueprint
│   └── README.md            API docs, index strategy, aggregation details
├── frontend/    React 19 + Vite SPA (deploy to Vercel or Netlify)
│   ├── src/                 components, API client, styles
│   ├── vercel.json          Vercel config
│   ├── netlify.toml         Netlify config
│   └── README.md            frontend setup and deploy guide
├── .nvmrc                   Node 22
└── README.md
```

## Requirements

- Node.js **22** (see `.nvmrc` in the root and in both packages)
- MongoDB — local for development, [MongoDB Atlas](https://www.mongodb.com/atlas) free
  tier for the deployed backend
- React **19** with Vite 7 on the frontend

## Local development

Two terminals:

```bash
# backend → http://localhost:4000
cd backend
cp .env.example .env                 # set JWT_SECRET
npm install
npm run seed:admin -- "Admin" admin@example.com "AdminPass123!"
npm run dev
```

```bash
# frontend → http://localhost:5173
cd frontend
cp .env.example .env                 # VITE_API_BASE_URL=http://localhost:4000/api
npm install
npm run dev
```

Backend environment variables are documented in [`backend/README.md`](backend/README.md)
(`MONGO_URI`, `JWT_SECRET`, `CORS_ORIGINS`, …). The frontend only needs
`VITE_API_BASE_URL` (defaults to `http://localhost:4000/api`).

## API and design

Full endpoint tables, status codes and pagination shape:
[`backend/README.md`](backend/README.md).

Highlights:

- `user` role: CRUD on their own notes and profile access.
- `admin` role: everything a user can do, plus user management (create/update/delete/list)
  and visibility into everyone's notes.
- bcrypt (cost 12) password hashing; hashes are never serialized.
- JWT verified on every request with the account re-loaded from MongoDB, so deleted
  accounts and role changes take effect immediately.
- Pagination (`page`, `limit` ≤ 100) on every list endpoint.
- Six documented indexes total, declared with `schema.index`, and nothing else:
  - User: `{email}` unique, `{createdAt,-_id}`, `{interests}` (multikey)
  - Note: `{owner,createdAt,-_id}`, `{createdAt,-_id}`
  - Post: `{author,createdAt,-_id}`
- Aggregation scenarios:
  - `GET /api/users/grouped-by-interests` — single `aggregate()` call
    (`$unwind → $group → $sort → $facet`).
  - `GET /api/users/:id/posts` — single pipeline with `$lookup` on `author`,
    pagination inside the lookup and a second `$lookup` for the total.

## Deployment

Deployment order matters: create the database, deploy the backend, deploy the frontend,
then allow the frontend origin in the backend's CORS configuration.

### 1. Database (MongoDB Atlas free tier)

1. Create a free M0 cluster.
2. Create a database user.
3. Allow network access from `0.0.0.0/0` (Render's free tier has no fixed egress IPs).
4. Copy the `mongodb+srv://...` connection string.

### 2. Backend on Render (free tier)

`backend/render.yaml` is a Render Blueprint with Node 22, `npm ci`, `npm start`,
health check `/api/health`, and a generated `JWT_SECRET`.

1. Push the backend to its own GitHub repository (commands below).
2. In Render: **New → Blueprint**, select the repository and apply it. Or create a Web
   Service manually with:
   - Runtime: Node, Node version `22`
   - Build command: `npm ci`
   - Start command: `npm start`
   - Health check path: `/api/health`
3. Set the environment variables:
   - `MONGO_URI` — the Atlas connection string
   - `CORS_ORIGINS` — the deployed frontend URL (e.g. `https://your-app.vercel.app`)
   - `JWT_SECRET` — generated by the blueprint, or a long random value
4. Seed an admin from your machine against Atlas:
   ```bash
   cd backend
   MONGO_URI="mongodb+srv://..." npm run seed:admin -- "Admin" admin@example.com "StrongPassword123"
   ```
5. Confirm `https://<your-service>.onrender.com/api/health` returns `{ "status": "ok" }`.

### 3. Frontend on Vercel or Netlify (free tier)

Vercel:

1. Push the frontend to its own GitHub repository, or import the monorepo and set
   **Root Directory** to `frontend`.
2. Import the repository in Vercel; Vite is auto-detected. `frontend/vercel.json` sets the
   build command, `dist` output and the SPA rewrite.
3. Add `VITE_API_BASE_URL=https://<your-service>.onrender.com/api`.
4. Deploy and copy the production URL.

Netlify:

1. **Add new site → Import an existing project**, select the repository.
2. Base directory `frontend`, build `npm run build`, publish `dist` — already declared in
   `frontend/netlify.toml`.
3. Add `VITE_API_BASE_URL` in **Site settings → Environment variables**, then deploy.

### 4. Close the loop

Add the deployed frontend URL to the backend's `CORS_ORIGINS` (comma separated, exact
origin, no trailing slash) and redeploy the backend. Sign in through the live frontend to
confirm end-to-end connectivity.

### Splitting into two GitHub repositories

The submission needs one repository per app. From the monorepo root, after creating two
empty GitHub repositories:

```bash
git subtree split --prefix=backend -b backend-deploy
git push git@github.com:<your-username>/secure-note-taking-backend.git backend-deploy:main

git subtree split --prefix=frontend -b frontend-deploy
git push git@github.com:<your-username>/secure-note-taking-frontend.git frontend-deploy:main
```

Alternatively keep the single repository and point the deployment platforms at the
`backend` and `frontend` root directories.

## Tests

Backend (needs a MongoDB instance; the test drops its own database):

```bash
cd backend
MONGO_URI="mongodb://127.0.0.1:27017/secure_note_taking_test" npm test
```

Covers auth, RBAC, ownership, pagination bounds, CORS, admin operations, both
aggregations, cascade deletion, the exact index set, and the query plans used by note
listings.

Frontend production build check:

```bash
cd frontend
npm run build
```
